## Key Corrections & Verifications
1. **Tenant Composite Integrity**:
   - `client_wallets(customer_id, tenant_id) REFERENCES customers(id, tenant_id)`
   - `client_wallet_ledger(wallet_id, tenant_id) REFERENCES client_wallets(id, tenant_id)`
   - `client_wallet_ledger(appointment_id, tenant_id) REFERENCES appointments(id, tenant_id)`
   - `gift_cards(purchaser_customer_id, tenant_id) REFERENCES customers(id, tenant_id)`
   - `gift_card_redemptions(gift_card_id, tenant_id) REFERENCES gift_cards(id, tenant_id)`
   - `gift_card_redemptions(customer_id, tenant_id) REFERENCES customers(id, tenant_id)`
   - `gift_card_redemptions(appointment_id, tenant_id) REFERENCES appointments(id, tenant_id)`
2. **Customer Tenant Verification Before Wallet Creation**:
   - `transact_wallet_balance` explicitly verifies `customer belongs to tenant` before auto-creating a wallet.
3. **Gift Card Redemption Boundary Verification**:
   - Proves customer and appointment belong to exact tenant before recording redemption.
4. **Narrowed Stored-Value Mutation Authority**:
   - Stored-value financial mutation is strictly restricted to `super_admin` or `tenant_owner`.
5. **Database-Enforced Append-Only Ledgers**:
   - Added `trg_prevent_wallet_ledger_mutation` and `trg_prevent_gift_card_redemptions_mutation` preventing any `UPDATE` or `DELETE`.
6. **Capability Code Protection**:
   - Raw gift card secret capability code is not stored in plaintext; stored as SHA-256 digest + masked identifier (`code_last_four`).
