## Key Corrections & Verifications
1. **Single Canonical Booking Engine (`RESOURCE_BOOKING_ENGINE_COUNT = 1`)**:
   - Eliminated parallel booking lifecycle from R1.
   - Resource evaluation, deterministic advisory locking, appointment insertion, and resource allocation are now strictly composed inside the canonical `create_public_booking` transaction.
   - All canonical invariants preserved: commercial eligibility, `max_monthly_appointments` quota, customer identity resolution, consent ledger, tokens, and idempotency.
   - Retained `create_booking_with_resources` as a backward-compatible wrapper delegating to canonical `create_public_booking`.
2. **Database-Level Composite Integrity**:
   - Added composite foreign key constraint `fk_appointment_resources_appointment_tenant` on `(appointment_id, tenant_id) REFERENCES public.appointments(id, tenant_id)`.
   - Maintained composite foreign key `(resource_id, tenant_id) REFERENCES public.resources(id, tenant_id)`.
3. **Atomicity Guarantee**:
   - `APPOINTMENT_INSERT_AND_RESOURCE_ALLOCATION_ATOMIC = YES`
   - Any resource allocation failure or exception rolls back the appointment creation in the same transaction.
