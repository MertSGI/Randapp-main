## Key Corrections & Invariant Enforcement

1. **Zero Quota Leakage on Failed Bookings (`ZERO_QUOTA_LEAKAGE_ON_FAILED_BOOKING`)**:
   - Reordered lifecycle gates in `public.create_public_booking`.
   - All pre-mutation validations now execute strictly **before** monthly appointment quota consumption:
     - Tenant validation & public status check
     - Commercial eligibility resolution & core booking gate
     - Branch resolution & active branch validation
     - Concurrency advisory lock
     - Idempotency replay check
     - Shared slot evaluator engine execution (`evaluate_booking_slot`, EV055-R3 schedule constraints)
     - Resource plan feasibility & deterministic advisory locking (`evaluate_and_lock_resource_plan`)
   - `consume_commercial_usage(v_tenant_id, 'max_monthly_appointments', v_period_key)` executes only after all validation and locking succeed.
   - Any expected validation failure returns immediately before quota mutation, preventing quota consumption.

2. **Atomic Rollback Guarantee on Post-Quota Mutation Failure**:
   - If any exception occurs after quota consumption (during customer upsert, consent ledger, appointment insert, resource allocation, or token generation), the exception block raises `BOOKING_MUTATION_FAILED` to force total transaction rollback in PostgreSQL, ensuring zero quota leakage.
