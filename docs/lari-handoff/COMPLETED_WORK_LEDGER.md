## 1. Proof-Level Classification & Gap Taxonomy

Every LARİ capability and work package is classified below using two orthogonal dimensions:

### A. Proof Levels (A capability may hold multiple proof levels)
- **`IMPLEMENTED_SOURCE_VERIFIED`** — SQL migrations, TypeScript services/repositories, and React UI components exist and are verified in `MertSGI/Randapp-main` source.
- **`TESTED_LOCAL`** — Verified by local contract, behavioral, or disposable PostgreSQL test harnesses (`scripts/test-*.mjs`, `supabase/tests/*.sql`).
- **`HOSTED_CI_VERIFIED`** — Verified by passing GitHub Actions workflow runs (`LARI QA`, `LARI Product Convergence L1-L4`, `LARI Program V2 Phase 5 Disposable Postgres Acceptance`, `LARI P0 PostgreSQL 17 Security`, `LARI PG17 Role Restore Qualification`, etc.).
- **`CANONICALLY_ACCEPTED`** — Bound to an immutable accepted LARİ checkpoint (`06ebf176e411faf6820ded34987f894cc5e7dc9e` for Phase 1–7 + WP5; `b0abd72536d665aaed334c48f69b68e1d8806942` for L1–L4 Product Convergence; `72911e4fb68dd4f85f7fafef575089104102064e` for C1–C4 Release Gates).
- **`STAGING_VERIFIED`** — Applied to and verified on the persistent Supabase staging project `lari-staging` (`rwedeejhjazwjthdjzrt`).
- **`BROWSER_E2E_VERIFIED`** — Verified in real headless Chromium via Playwright (`npm run qa:ui-v2-booking-e2e`, `npm run qa:ui-v2-booking-integrity`, `npm run qa:product-flow`).
- **`PRODUCTION_PROVEN`** — Proven in live customer production (`NONE` — production remains `NO_GO`).
- **`INCOMPLETE / BLOCKED / UNKNOWN`** — Explicitly identifies remaining operational, live-migration, or external-provider gaps.

### B. Differentiation of Remaining Gaps (Never Redevelop Code When Only Migration/Ops Is Pending)
- **`NONE_COMPLETE_IN_SOURCE`** — Code, tests, and CI are complete; only downstream operational/merge steps apply.
- **`MISSING_DEFAULT_BRANCH_MERGE`** — Present on `72911e4fb68dd4f85f7fafef575089104102064e` (or PR `#3` `2b238ed6...`), not yet merged into `staging/supabase-staging-consistency` (`c8dfd3d2...`).
- **`MISSING_STAGING_MIGRATION`** — SQL migration is complete and CI-verified in disposable PostgreSQL, but not yet applied to live `rwedeejhjazwjthdjzrt` (or requires version-collision/drift reconciliation per `docs/evidence/migration-reconciliation-20261011.json`).
- **`MISSING_DEPLOYMENT`** — Edge function or preview/production deployment cutover not yet executed.
- **`MISSING_EVIDENCE`** — Requires live backup artifact (`VERIFIED_LOGICAL_RESTORE`), owner environment readback, or post-P0 synthetic staging E2E execution (`docs/LARI_STAGING_SYNTHETIC_E2E_PLAN.md`).
- **`MISSING_CODE`** — True unbuilt feature (only applicable to future post-pilot live payment gateway or live SMS/WhatsApp provider cutover).
